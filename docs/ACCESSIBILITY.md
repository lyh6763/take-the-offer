# 접근성 점검 — KWCAG 2.2

한국형 웹 콘텐츠 접근성 지침 2.2의 33개 검사항목으로 이 앱을 점검한 기록입니다. 첫 점검의 미흡 3건을 고친 뒤 같은 방법으로 다시 점검했습니다. 재점검에서 아지트 메뉴의 영문 장식이 위치에 따라 4.5:1 아래로 내려가는 것을 찾아 이것도 고치고 다시 쟀습니다(아래 '수정 기록').

## 점검 기준

- **표준**: 한국형 웹 콘텐츠 접근성 지침 2.2 (KS X OT0003:2022). 표지에는 방송통신표준심의회, 2022년 12월 28일 개정으로 적혀 있습니다. 4개 원칙, 14개 지침, 33개 검사항목으로 구성됩니다.
- **확인 방법**: 같은 날 다른 포트폴리오 점검에서 받아 둔 표준 원문 PDF를 다시 읽었습니다. 이 앱에 걸리는 항목(5.2.1, 5.3.2, 5.4.2, 5.4.3, 6.1.2, 6.1.4, 6.2.1, 6.2.2, 6.3.1, 7.2.1, 7.2.2, 7.3.1~7.3.4, 8.1.1)은 본문을 대조했습니다.
- **판정 규칙**
  - 통과: 점검한 모든 화면에서 요구사항을 충족함
  - 미흡: 한 곳이라도 충족하지 못함
  - 해당 없음: 항목이 다루는 콘텐츠(표, 인증 등)가 없음
- **미확인**
  - 원문 PDF는 웹에이전시 사이트(websoul.co.kr)에 게시된 사본입니다. 표준 배포처인 국립전파연구원(rra.go.kr)의 원본과 같은 판인지는 대조하지 못했습니다.
  - 인증 심사 기관의 세부 판정 기준은 확인하지 않았습니다. 이 문서의 판정은 표준 본문을 기준으로 한 자체 판단입니다.
  - 표준 원문에는 테두리를 두른 글자의 대비 계산법이나 비활성 컨트롤의 예외가 따로 적혀 있지 않습니다. 이 둘은 W3C의 WCAG 2.1 해설(Understanding SC 1.4.3)을 참고해 판단했고, 해당 항목에 그렇게 적었습니다.
  - 점검 브라우저는 Chrome 하나입니다. Web Speech API(음성 합성·음성 인식)는 브라우저마다 지원이 달라, Safari·Firefox에서의 동작은 확인하지 않았습니다.
- **보조 점검**: 33개 검사항목 중 '확대 시 가로 스크롤(리플로)'과 'prefers-reduced-motion'을 직접 다루는 항목은 없습니다. 그래서 이 둘은 결과표와 별도로 기록했습니다. 앞의 것은 WCAG 2.1의 1.4.10 리플로에 해당합니다. 뒤의 것은 KWCAG 6.2.2 정지 기능 제공과 함께 봤습니다.

## 도구와 방법

| 도구 | 버전 | 용도 |
| --- | --- | --- |
| axe-core | 4.14.0 | 자동 점검. 태그 `wcag2a` `wcag2aa` `wcag21a` `wcag21aa` `wcag22aa` `best-practice` |
| Chrome (headless) | 155.0.8059.84 | 점검 브라우저. 한국어 음성(Microsoft Heami)이 있어 질문 낭독이 실제로 재생됨 |
| playwright-core | 1.64.1 | 브라우저 조작(화면 크기, 키보드 입력, 움직임 줄이기 설정 흉내, localStorage 데이터) |
| html-validate | 9.7.1 | 마크업 문법 검사(`html-validate:standard` 프리셋) |
| Node.js | 24.13.0 | 아래 점검 스크립트 실행(저장소에는 넣지 않음) |

- **자동 점검**: 17개 화면마다 데스크톱(1440×900)과 모바일(375×812) 두 크기에서 axe를 돌렸습니다. 페이지 끝까지 한 번 스크롤한 뒤 실행했습니다.
- **수동 점검을 돕는 스크립트**
  - Tab 키만 눌러 초점이 가는 순서를 기록했습니다. 화면을 열면 앱이 제목(h1)으로 초점을 옮기므로, '본문 바로가기'에서 시작하는 순회도 따로 했습니다. 날짜 입력칸은 연·월·일 칸마다 Tab이 멈추므로 같은 요소가 반복돼도 함정으로 보지 않았습니다.
  - Shift+Tab으로 거꾸로도 순회했습니다. 초점이 간 요소 위 9개 지점을 `elementFromPoint`로 확인해 다른 요소(상단 고정 HUD 등)에 가려졌는지 쟀습니다. 가려지거나 화면 밖으로 잡힌 경우는 캡처로 다시 봤습니다.
  - 초점이 있을 때와 뺐을 때 화면을 비교해 초점 표시가 보이는지 쟀습니다. 모양만 바꾼 라디오(실제 input은 투명)는 그 label 영역으로 비교했습니다. 375px 날짜 입력칸은 모바일 흉내에서 초점이 빠지지 않아 차이가 0으로 나오므로 캡처로 확인했습니다(초점 때 노란 테두리가 보임).
  - 키보드로 조작하며 상태를 기록했습니다. 대상은 새 팰리스 등록(빈 이름 제출 오류 포함), 키워드·질문 추가와 삭제, 팰리스 삭제와 모두 지우기 대화상자, 잘못된 파일 불러오기, 예고장 보내기, 잠입(직접 입력·말로 답하기), 질문 낭독 멈추기, 컷인 건너뛰기, 아지트 방향키 메뉴, 타이틀 시작과 뒤로 가기입니다.
  - 말로 답하기는 실제 마이크 대신 가짜 음성 인식 객체로 바꿔 확인했습니다. 중간 결과, 확정 결과, 오류 3가지(`not-allowed`, `no-speech`, `network`)를 흉내 냈습니다.
  - 질문 낭독 시간은 질문 은행 26개, 회사 맞춤 질문 2개, 설정의 목소리 샘플 1개를 속도 1.0으로 실제 재생해 쟀습니다.
  - 320px(1280px 화면을 400% 확대한 너비)와 640px(200%)에서 가로 스크롤이 생기는지 확인했습니다. 17개 화면과 잠입 질문·판정 단계, 컷인, 대화상자 2개를 봤습니다.
  - 375px에서 링크·버튼·입력 크기를 재서 표준이 권하는 대각선 6.0mm(약 22.7 CSS px) 미만인 것을 찾았습니다. 작은 것은 `elementFromPoint`로 실제로 눌리는 범위를 다시 재도록 했습니다.
  - 움직임 줄이기(`prefers-reduced-motion: reduce`) 설정과 앱의 모션 설정(기기 설정 따르기·항상 줄이기·줄이지 않기)을 조합해 실행 중인 애니메이션을 비교했습니다.
  - axe가 판단하지 못한 명도 대비(그라데이션·회전하는 빛줄기 배경 위 글자, CSS로 만든 글자, 컷인)는 화면 캡처로 다시 쟀습니다. 글자를 투명하게 만든 화면과 원래 화면을 비교해 글자 획 아래 배경 픽셀만 고르고, 하위 5% 대비값으로 판정했습니다. 글자색에는 조상 요소의 투명도까지 곱했고, SVG 글자는 `fill`을 글자색으로 썼습니다. 배경 빛줄기는 계속 돌기 때문에 무늬 한 주기를 12단계로 나눠 가장 낮은 값을 썼습니다. 글자는 화면 가운데로 스크롤해 쟀습니다(맨 위에 붙어 가운데로 못 오는 글자는 그 자리에서). 배경은 화면에 고정돼 돌고 글자는 스크롤되므로, 아지트 메뉴 영문 장식은 화면 위·가운데·아래 3곳 × 12위상으로 따로 쟀고 초점 상태도 쟀습니다. 컷인은 자동으로 닫히지 않게 멈춘 뒤 등장 애니메이션이 끝난 상태에서 쟀습니다.
- **마크업 검사**: 빌드된 `index.html`은 빈 `#root` 하나뿐이라, 화면마다 렌더된 DOM을 HTML 파일로 저장해 함께 검사했습니다(19개: 위 17개 화면과 잠입 질문·판정 단계).
- **재점검**: 수정 뒤 새로 빌드해 위 도구와 스크립트를 그대로 다시 돌렸습니다. 낭독 멈추기 시나리오를 추가했습니다. 타입 검사(`npm run typecheck`), 테스트 17개(`npm test`), 빌드도 통과했습니다.
- **하지 않은 것**: 스크린리더(NVDA, 센스리더, VoiceOver) 실사용, 실제 모바일 기기, 실제 마이크와 음성 인식 서버, 브라우저 확대 기능 자체(320px 화면으로 대신함), 고대비 모드, View Transitions 화면 전환이 진행되는 도중의 상태.

## 개선 권장(미흡은 아님)

1. **삭제 뒤 초점**(`PalaceDetail.tsx:124`, `151`): 키워드나 질문의 삭제 버튼을 누르면 버튼이 사라지면서 초점이 문서 처음(`body`)으로 갑니다. Chrome에서는 다음 Tab이 다음 삭제 버튼으로 이어지지만, 스크린리더 사용자는 위치를 잃을 수 있습니다. 지운 뒤 다음 항목의 삭제 버튼이나 추가 입력칸으로 초점을 옮기면 좋습니다.
2. **녹음 경과 시간**(`Infiltrate.tsx:322`): 시계와 실시간 인식 문장이 `aria-hidden`이라 화면을 보지 못하면 얼마나 말했는지 모릅니다. 매초 읽히면 방해가 되므로, 녹음을 마칠 때 상태 알림에 답변 시간을 넣는 방법("녹음을 마쳤습니다. 1분 12초.")이 간단합니다.
3. **목소리 샘플 문장**(`Settings.tsx:78`): '목소리 들어 보기'가 읽는 문장을 버튼 옆에 글로 보여 주면 5.2.1 판단에 여지가 없어집니다.
4. **진행 표시 "QUESTION 1/3"**(`screens.css:530-537`): 흰 테두리 덕에 통과로 봤지만, 채움색만 보면 375px에서 2.57:1입니다. 채움색을 `--red-text`로 바꾸면 테두리에 기대지 않아도 됩니다.
5. **고를 수 없는 선택지**(`components.css:392-394`): 투명도 0.45로 4.37:1입니다. WCAG는 비활성 컴포넌트를 예외로 두지만 KWCAG 원문에는 그 예외가 명시돼 있지 않습니다. 투명도를 0.5로 올리면 계산값 5.10:1입니다.
6. **타이틀 화면의 회전 배경**: 타이틀에는 HUD가 없어, 기기의 움직임 줄이기를 켜지 않은 사용자는 빛줄기 회전을 멈출 수단이 화면에 없습니다. '작전 개시' 한 번이면 설정에 갈 수 있어 통과로 봤지만, 타이틀에 모션 끄기 토글을 두면 더 확실합니다.
7. **문서 제목**: 팰리스 상세의 제목에 회사 이름을 넣으면("한빛소프트 — 팰리스 조사 | TAKE THE OFFER") 탭·기록에서 구분하기 쉽습니다.
8. **자동 낭독 기본값**: 낭독은 이제 멈출 수 있지만, 기본값이 켜짐이라 질문 제목으로 초점이 갈 때 화면낭독 프로그램과 면접관 목소리가 동시에 시작됩니다. 웹에서는 화면낭독 프로그램을 쓰는지 알 수 없어 자동으로 끌 수는 없습니다. 기본값을 끔으로 바꾸거나, 잠입 설정의 체크박스 옆에 "화면낭독 프로그램을 쓰면 끄기를 권장" 같은 안내를 두는 방법이 있습니다.
9. **제목 뒤 영문 장식**(`components.css:92-102`): "HIDEOUT"·"INFILTRATE" 등은 장식이라 대비 계산에서 뺐습니다. 채움색만 보면 375px에서 최저 2.68:1입니다. 아지트 메뉴 영문처럼 검정 띠를 깔거나 채움색을 `--red-text`로 바꾸면 장식 판단에 기대지 않아도 됩니다.
